Cuando algo sale mal, ¿quién se hace cargo?

Un programa que divide por cero o recibe letras donde esperaba números se detiene de golpe. En esta clase aprendemos a anticipar esos errores, atraparlos y decidir qué hacer con ellos.

def dividir(x, y): return x / y x = float(input("x: ")) y = float(input("y: ")) try: print(dividir(x, y)) except ZeroDivisionError: print("No se puede dividir por cero") print("Finalizado")

x: 4 y: 0 Traceback (most recent call last): File "clase9.py", line 6, in <module> print(dividir(x, y)) File "clase9.py", line 2, in dividir return x / y ZeroDivisionError: float division by zero

Control de ciclos

Antes de las excepciones necesitamos dominar tres herramientas para cortar o saltear vueltas de un ciclo. Son las que después combinaremos con try.

break y continue

Las dos rompen el flujo normal de un while o un for:

  • continue termina la vuelta actual y salta directamente a la siguiente. Lo que queda debajo en el bloque no se ejecuta en esa vuelta.
  • break sale del ciclo por completo, aunque la condición siga siendo verdadera.
continue: suma de dígitos pares
break: suma de los últimos 5 dígitos
def sumaDigitosPares(nro):
    suma = 0
    while nro > 0:
        digito = nro % 10
        nro = nro // 10
        if digito % 2 != 0:
            continue  # salta a la siguiente vuelta
        suma = suma + digito
    return suma

n = int(input("Ingrese un número: "))
print("Suma de dígitos pares:", sumaDigitosPares(n))
def sumaUltimosDigitos(nro):
    suma = 0
    cantd = 0
    while nro > 0:
        digito = nro % 10
        nro = nro // 10
        suma = suma + digito
        cantd += 1
        if cantd == 5:
            break  # sale del ciclo
    return suma

n = int(input("Ingrese un número: "))
print("Suma últimos 5:", sumaUltimosDigitos(n))

Usalos con moderación. El abuso de break y continue vuelve el código difícil de seguir. Muchas veces la condición de salida puede escribirse en un solo lugar, junto al while:

def sumaUltimosDigitos(nro):
    suma = 0
    cantd = 0
    while nro > 0 and cantd < 5:   # toda la condición de salida acá
        digito = nro % 10
        nro = nro // 10
        suma = suma + digito
        cantd += 1
    return suma

print(sumaUltimosDigitos(123456789))

La cláusula else del while

Un while puede tener un else. Ese bloque sólo se ejecuta si el ciclo terminó porque su condición resultó falsa. Si se salió con break, el else se saltea. Es ideal para búsquedas: «recorrí todo y no lo encontré».

lista = [3, 23, 45, 18, 32, 8]
nro = int(input("Ingrese un número a buscar: "))
i = 0
while i < len(lista):
    if nro == lista[i]:
        print("El nro se encontró en la ubicación", i)
        break
    i = i + 1
else:
    print("El nro no se encontró")

while True

while True es un ciclo infinito a menos que dentro exista una condición que lo corte con break. Es útil cuando no se sabe de antemano cuántas vueltas habrá, como al leer datos hasta un valor centinela.

# Sumar números hasta que se ingrese -1
suma = 0
while True:
    nro = int(input("Ingrese un número: "))
    if nro == -1:
        break
    suma = suma + nro
print("La suma es:", suma)
Mala práctica: emular un for
Lo correcto
i = 0
while True:
    if i >= 10:
        break
    print(i, end=" ")
    i = i + 1
for i in range(10):
    print(i, end=" ")

Si la cantidad de vueltas se conoce, se usa for. El while True queda para cuando el fin depende de lo que pase adentro, y va a ser nuestro gran aliado para volver a pedir un dato hasta que sea válido.

Las excepciones son el mecanismo de Python para los errores de ejecución: permiten determinar qué hace el programa cuando algo falla, capturando el error y desviando el flujo hacia un bloque que lo trate.

Cómo leer un traceback

Cuando nadie atiende una excepción, Python muestra un traceback: el recorrido de llamadas que llevó al error. Se lee de abajo hacia arriba: la última línea dice qué pasó, y las de arriba, por dónde pasó.

Traceback (most recent call last):
  File "programa.py", line 7, in <module>     ← 3. empezó acá: z = g(5, 0)
    z = g(5, 0)
  File "programa.py", line 5, in g            ← 2. g llamó a f
    return f(x, y)
  File "programa.py", line 2, in f            ← 1. acá ocurrió
    return x / y
ZeroDivisionError: division by zero           ← tipo: descripción

Propagación

Si dentro de una función surge una excepción y la función no la maneja, la excepción se propaga a la función que la llamó. Si esa tampoco la maneja, sigue subiendo hasta el marco global. Si nadie la atrapa, el programa se interrumpe. Se puede atrapar en cualquier nivel de la cadena.

marco global → main()

try / except

    
El código que puede fallar va en el bloque try. Si ocurre una excepción, el resto del try se saltea y Python busca un except cuyo tipo coincida. Si no ocurre nada, los except se saltean.

    

      
Capturar un error

      
Capturar varios errores


try:
    <instrucciones>
except TipoDeError:
    <instrucciones>


try:
    <instrucciones>
except Tipo1:
    <instrucciones>
except (Tipo2, Tipo3):   # mismo tratamiento
    <instrucciones>
except Exception:        # cualquier otro
    <instrucciones>

    

    
Con as se le pone nombre a la excepción para consultar su tipo y su mensaje:

    
try:
    int("abc")
except ValueError as err:
    print(f"Tipo de error: {type(err).__name__}")
    print(f"Descripción del error: {err}")

    

      
El orden de los except importa. Python usa el primero que coincide, y un tipo general también atrapa a sus “hijos”: ZeroDivisionError es un ArithmeticError, que es una Exception. Por eso los más específicos van primero y except Exception al final.

      
Evitá el except: sin tipo. Atrapa absolutamente todo, incluso errores de tipeo como un NameError, y los esconde. Si necesitás un “atrapa todo”, usá except Exception:.

    


    

    


    
Reintentar: while True + try

    
Capturar el error evita que el programa se caiga, pero el dato sigue sin estar. Combinando while True con try se puede volver a pedir hasta que la entrada sea válida: el break va al final del try, así sólo se alcanza cuando todo salió bien.

    
while True:
    try:
        nro1 = int(input("Ingrese un número: "))
        nro2 = int(input("Ingrese un número: "))
        divi = nro1 // nro2
        print(f"La división entre {nro1} y {nro2} es {divi}")
        break   # si llega acá, todo el bloque salió bien
    except ValueError:
        print("Error, se esperaba que ingrese un número entero.")
    except ZeroDivisionError:
        print("Error. División por cero.")

try:

raise: lanzar una excepción

    
Hasta acá atrapamos errores que produce Python. Con raise los producimos nosotros cuando detectamos una condición inválida, eligiendo el tipo y el mensaje:

    
raise Exception("Algo salió mal")
raise ValueError("El número debe ser positivo")
raise TypeError("El parámetro debe ser una lista")

    
x = "Hola mundo!"
if not type(x) is int:
    raise TypeError("Sólo se permiten valores enteros.")

    
Elegí el tipo que mejor describe el problema: ValueError si el tipo es correcto pero el valor no sirve, TypeError si el tipo es incorrecto.


    
raise sin argumentos: re-lanzar

    
Dentro de un except, un raise solo vuelve a lanzar la excepción que se está atendiendo. Sirve para hacer algo (avisar, registrar) y dejar que el error siga su camino hacia quien llamó.

    
while True:
    try:
        num = int(input("Ingrese un número: "))
        break
    except ValueError:
        print("Error, se esperaba que ingrese un número entero.")
        resp = input("¿Desea volver a ingresar un número? (s/n): ")
        if resp.lower() != "s":
            raise   # le di una oportunidad; si no la quiere, el error sigue su curso
        print("Vuelva a ingresarlo")


    

    
Remarcar la diferencia de roles: la función que valida lanza (raise) y no imprime; el programa que la usa captura (except) y decide cómo informar al usuario.

assert y validaciones


    
assert

    
assert condición no hace nada si la condición es verdadera. Si es falsa, lanza AssertionError. Se le puede agregar un mensaje para saber cuál falló:

    
palabra = input("Ingrese una palabra: ")
try:
    assert len(palabra) > 5, "Palabra muy corta"
    assert palabra.isalpha(), "Sólo se permiten letras"
    print("Palabra válida")
except AssertionError as mensaje:
    print(mensaje)

    
Un detalle profesional: los assert pueden desactivarse al ejecutar Python con python -O. Por eso en proyectos reales se usan para verificar supuestos del programador durante la depuración, y para validar datos del usuario se prefiere un if con raise. En la materia los usamos también para validar entradas porque son claros y breves.


    


    
Precondiciones

    
Las precondiciones son las condiciones que deben cumplirse antes de ejecutar una función para que funcione correctamente. promedio(L) tiene dos implícitas: L no debe estar vacía y debe contener sólo números.

    

      
Validar con raise

      
Validar con assert


def promedio(L):
    if len(L) == 0:
        raise ValueError("La lista no debe estar vacía")
    return sum(L) / len(L)

promedio([])


def promedio(L):
    assert len(L) > 0
    return sum(L) / len(L)

promedio([])

    

    
En los dos casos el programa se detiene, pero ahora con un mensaje que explica la causa real, en lugar de un ZeroDivisionError que no dice nada sobre la lista.


    
Validar la entrada del usuario

    
Un try que atrapa el error una sola vez no alcanza: el segundo intento queda desprotegido. La versión robusta repite hasta que el dato sea válido.

    

      
Limitada

      
Robusta


def pedir_numero_1(mensaje):
    valor = input(mensaje)
    try:
        num = float(valor)
    except ValueError:
        print("Ha ocurrido un error!")
        valor = input(mensaje)
        num = float(valor)   # sin protección
    return num

print(pedir_numero_1("Valor: "))


def pedir_numero_2(mensaje):
    while True:
        valor = input(mensaje)
        try:
            num = float(valor)
            break
        except ValueError:
            print("Ha ocurrido un error!")
    return num

print(pedir_numero_2("Valor: "))
